# Excel 格式测试用例参考

用户指定"Excel格式"或"xlsx格式"或"Excel测试用例"或"xlsx测试用例"或"表格测试用例"时，按本文件输出 Excel (.xlsx) 测试用例。本文件供 SKILL.md 步骤 4 引用。

## 字段说明

遵循轻量标准 11 列表格结构，所有用例数据平铺排列在 `测试用例` 工作表中：

| 字段 | 是否必填 | 来源与说明 |
| :--- | :---: | :--- |
| 需求/追踪 ID | 是 | 需求编号、验收标准编号或稳定的来源标识（如 `REQ-001`、`US-1024`） |
| 用例 ID | 是 | 全局唯一标识，建议格式：`TC-模块简写-流水号`（如 `TC-AUTH-001`） |
| 用例标题 | 是 | 结构化命名，体现测试目的，建议格式：`[模块]_[功能]_[场景]_[预期结果]` |
| 用例类型 | 是 | 功能测试、回归测试、性能测试、安全测试等一级类型；异常测试、边界值测试等功能测试细分场景也可使用 |
| 设计方法 | 是 | 等价类划分、边界值分析、判定表法、状态迁移法、错误推测法、正交试验等 |
| 优先级 | 是 | `P0`（冒烟/阻塞级）、`P1`（核心功能）、`P2`（重要功能）、`P3`（一般/轻微）、`P4`（特殊边界） |
| 前置条件 | 是 | 执行前必需的前提条件（环境、账号状态、依赖就绪、测试底据），多项使用换行有序列表 |
| 测试数据 | 否 | 具体入参、构造账号、脱敏占位符等，多项使用换行有序列表 |
| 执行步骤 | 是 | 明确且可复现的动作，编号递增（如 `1. ...\n2. ...`），多项使用换行有序列表 |
| 预期结果 | 是 | 针对检查点的确定性、可观测断言（界面提示、报文属性、业务状态、落库），多项使用换行有序列表 |
| 备注 | 否 | 风险提示、Teardown 后置环境恢复说明、自动化执行建议等 |

模板文件 `assets/excel-test-case-template.xlsx` 中的示例数据行仅用于示意字段结构，生成产物必须全部替换为本次用例，不得保留示例行。

## 工作簿布局与样式规范

1. **主工作表 (`测试用例`)**：
   - **第 1 行（大标题）**：合并 `A1:K1` 单元格，文字居中，16pt 加粗（内容如 `测试用例 - {上线日期} - [{需求名称}]`），行高 30。
   - **第 2 行（表头）**：严格按照 11 个标准列头排列，背景色为 `#D9EAF7`，11pt 加粗，居中对齐，浅蓝灰细边框，行高 24。
   - **第 3 行及之后（用例数据）**：
     - 一行对应一条用例。
     - 单元格文字多项内容使用换行符分隔，启用自动换行（Wrap Text）。
     - 类型、设计方法、优先级列采用水平居中、垂直居顶；其他长文本列采用水平居左、垂直居顶。
     - 细边框包裹，动态估算自适应行高。
   - **冻结窗格与筛选**：冻结首部至 `A3`；表头区域开启自动筛选（AutoFilter `A2:K{n}`）。
   - **列宽设置**：预设合理列宽（需求ID: 18, 用例ID: 18, 标题: 36, 类型: 12, 方法: 18, 优先级: 10, 前置: 32, 数据: 26, 步骤: 44, 预期: 44, 备注: 26）。

2. **附带说明工作表 (`生成说明`)**：
   - 记录元数据：`需求名称`、`上线日期`、`用例数量`、`覆盖范围`、`需求存疑与待确认清单`、`补充说明`。

## 用例设计与真实性准则

用例设计、覆盖与真实性要求遵循 [测试规则](test-rules.md)。Excel 特有要求：

- 前置条件、测试数据与执行步骤的多项内容使用换行有序列表。
- 涉及全局配置变更或数据占用的用例，在前置数据中使用隔离占位符，并在备注或预期结果中注明后置清理/恢复操作（Teardown）。

## 存疑清单呈现

需求存疑与待确认清单记录在 `生成说明` 工作表的“需求存疑与待确认清单”字段，对有依据且可判定的假设用例，在用例标题中标记 `[待确认]`。用户确认后的反向优化、清单删除与重新校验按 SKILL.md 第 6 步执行。

## 校验规则

- 必须包含名为 `测试用例` 和 `生成说明` 的工作表。
- 第 2 行必须完全匹配 11 个标准列头且顺序一致：`需求/追踪 ID`、`用例 ID`、`用例标题`、`用例类型`、`设计方法`、`优先级`、`前置条件`、`测试数据`、`执行步骤`、`预期结果`、`备注`。
- 必填字段（需求/追踪 ID、用例 ID、用例标题、用例类型、设计方法、优先级、前置条件、执行步骤、预期结果）在每条数据行均不能为空。
- `用例 ID` 必须全局唯一，不得重复。
- `用例标题` 在同一工作簿中不得重复。
- `优先级` 必须为 `P0`、`P1`、`P2`、`P3`、`P4` 之一。
- 生成后必须执行校验脚本进行合规核对：

  ```bash
  python "{技能根目录}/scripts/validate_excel_cases.py" <文件路径>
  ```

  校验通过前不得交付；若发现错误，先修正工作簿产物后再次校验。

## 生成脚本推荐

当智能体已整理好用例的结构化 JSON 数据时，推荐直接调用技能内置的构建脚本一键生成样式完备的工作簿：

```bash
python "{技能根目录}/scripts/create_excel_cases.py" \
  --output "<输出绝对路径.xlsx>" \
  --title "测试用例 - {上线日期} - [{需求名称}]" \
  --input-json "<包含cases数组与meta的临时json路径>"
```

输入 JSON 结构如下（`meta` 可省略；数组字段可改为多行字符串）：

```json
{
  "meta": {
    "title": "测试用例 - {上线日期} - [{需求名称}]",
    "requirement_name": "{需求名称}",
    "release_date": "{上线日期}",
    "coverage": "覆盖范围",
    "open_questions": "需求存疑与待确认清单",
    "notes": "补充说明",
    "sheet_name": "测试用例"
  },
  "cases": [
    {
      "requirement_id": "REQ-001",
      "id": "TC-MODULE-001",
      "title": "[模块]_[功能]_[场景]_[预期结果]",
      "type": "功能测试",
      "design_method": "等价类划分",
      "priority": "P1",
      "preconditions": ["前置条件1", "前置条件2"],
      "test_data": ["测试数据1"],
      "steps": ["执行步骤1", "执行步骤2"],
      "expected_results": ["预期结果1", "预期结果2"],
      "notes": "备注"
    }
  ]
}
```

`--input-json` 为必填参数。`meta.sheet_name` 可覆盖主工作表名称（默认 `测试用例`）。`生成说明` 工作表由脚本始终创建，`用例数量` 按 `cases` 数组长度自动写入，无需手工填写。

生成完成后，立即调用 `validate_excel_cases.py` 进行静态校验。
