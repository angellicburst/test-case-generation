# Excel 格式测试用例参考

用户指定 Excel/xlsx/表格格式时按本文件输出 `.xlsx`；用例设计规则见[测试规则](test-rules.md)。工作簿由 `render_cases.py` 从临时 IR 生成，不手工拼接。

## 字段说明

主工作表每行一条用例，固定 11 列，顺序不得调整：

| 列 | 字段 | 必填 | 来源与说明 |
| :---: | :--- | :---: | :--- |
| A | 追溯 ID | 是 | 关联追溯条目的 ID，多个用 `, ` 分隔，顺序与追溯表一致 |
| B | 用例 ID | 是 | `TC-{需求简写}-{3 位流水号}`，全局唯一，永久主键 |
| C | 用例标题 | 是 | 体现测试目的，同一工作簿内唯一；不含用例 ID |
| D | 用例类型 | 是 | 功能测试、回归测试、性能测试、安全测试、兼容性测试、易用性测试、可靠性测试 |
| E | 设计方法 | 是 | 等价类划分、边界值分析、判定表法、状态迁移法、错误推测法、正交试验、场景分析法 |
| F | 优先级 | 是 | `P0`–`P4`，定义见[测试规则](test-rules.md#用例优先级) |
| G | 前置操作 | 是 | 执行前的环境、账号与数据状态；多项换行，带 `1. `、`2. ` 序号 |
| H | 测试数据 | 否 | 入参、构造账号、脱敏占位符；多项换行 |
| I | 测试步骤 | 是 | 可复现的操作，编号递增；多项换行 |
| J | 预期结果 | 是 | 确定、可观测的断言；多项换行 |
| K | 后置操作 | 否 | 数据清理或环境恢复；不得与测试步骤重复 |

## 工作簿布局

1. **`测试用例`**（主表，名称取自 IR `meta.sheet_name` 或 `create_excel_cases.py --sheet-name`，默认 `测试用例`）：
   - 第 1 行合并 `A1:K1` 作为大标题，内容 `测试用例 - {日期} - [{需求名称}]`，居中、16pt 加粗、行高 30。
   - 第 2 行固定 11 个表头，浅蓝底、11pt 加粗、居中、行高 24。
   - 第 3 行起为数据；启用自动换行与细边框，类型/设计方法/优先级居中，其余左对齐、垂直居顶，行高按内容估算（24–409）。
   - 冻结至 `A3`；自动筛选 `A2:K{末行}`；只允许 A–K 列。
   - 列宽：22, 18, 36, 12, 18, 10, 32, 26, 44, 44, 32。
2. **`生成说明`**：
   - `A1` 为标题并合并 `A1:B1`，不得有其他合并区域。
   - 第 2–6 行依次为 `需求名称`、`上线日期`、`用例数量`、`覆盖范围`、`补充说明`，每个标签只出现一次；前三个必填。
   - `上线日期` 为 `YYYY-MM-DD` 或 `未指定日期`；`用例数量` 为整数且等于主表实际用例行数。
   - 只允许 A、B 两列有内容。
3. **`需求追溯`**：
   - `A1` 为 `需求追溯表` 并合并 `A1:E1`；第 2 行表头为 `追溯 ID`、`来源`、`定位`、`规则`、`关联用例 ID`；第 3 行起为 `已覆盖` 条目，至少 1 行（`待覆盖` 仅存在于起草期临时 IR，渲染时自动结算并拦截残留）。
   - 冻结 `A3`，筛选 `A2:E{末行}`，只允许 A–E 列。
4. **`待确认项`**（仅当存在待确认条目时创建，不得留空壳）：
   - `A1` 为 `待确认项清单` 并合并 `A1:F1`；第 2 行表头为 `追溯 ID`、`来源`、`定位`、`未明确项`、`当前测试假设`、`确认问题`；至少 1 行数据。
   - 冻结 `A3`，筛选 `A2:F{末行}`，只允许 A–F 列。

工作表名不得使用保留名 `生成说明`、`需求追溯`、`待确认项`。使用 `render_cases.py` 时在 IR `meta.sheet_name` 配置主表名；后续校验、导出、同步均需传同一 `--sheet-name`。

## 真实性准则

- 所有单元格按纯文本写入；第 1、2 行与数据行出现公式均不合规，`=1+1`、`+1+1`、`-1+1`、`@SUM(1)` 等按文本保存。
- IR 的 `meta`、`traceability`、`cases` 全部字段均不得保留 `[待确认]` 标记；`meta.case_count` 不得手填，用例数量按 `cases` 长度自动计算。
- 用例 ID 与标题在同一工作簿内唯一；标题不得以 `正向-`/`反向-` 开头或以 `-P0..P4` 结尾（极性、优先级由独立字段表达）；追溯 ID 在追溯表与待确认表中不得重复。
- 模板 `assets/excel-test-case-template.xlsx` 仅示意结构，生成产物必须替换全部示例数据；前置/后置、隔离、断言与追溯见[测试规则](test-rules.md)和[需求追溯规范](traceability-matrix.md)。

## 生成与校验

- 命令、覆盖确认、`openpyxl` 异常分级与文件占用处理见 `SKILL.md` 第 5 步及常用命令；`render_cases.py` 不接收 `--sheet-name`，主表名取自 `meta.sheet_name`。
- `validate_excel_cases.py` 检查工作表齐全性、A1 标题格式与生成说明一致性（`上线日期`、`需求名称`）、合并区域、表头、冻结与筛选、列范围、公式、必填字段、枚举、ID 与标题唯一性、数量一致性及追溯关联；失败须修正 IR 重渲染，不直接改单元格绕过校验。
