# Markdown 格式测试用例参考

用户指定"Markdown格式"或"MD格式"或"Markdown测试用例"或"MD测试用例"时，按本文件输出 Markdown 测试用例。本文件供 SKILL.md 步骤 4 引用。

## 字段说明

| 字段 | 说明 |
| :--- | :--- |
| 需求名称 | 从"步骤1"获取 `需求名称` |
| 用例数量 | 统计生成测试用例的数量 |
| 日期 | 从"步骤1"获取 `上线日期` |
| 功能点 | 从"步骤3"获取 `功能点` |
| 测试类型 | "测试类型"详见 [测试类型定义](test-rules.md#测试类型)，取 `一级类型` |
| 用例类型 | 正向 / 反向 |
| 用例标题 | 体现测试目的或测试点，如"1011加黑流程不处置场景" |
| 用例优先级 | "用例优先级"详见 [用例优先级定义](test-rules.md#用例优先级) |
| 前置条件 | 执行用例需要的前提条件（环境/参数/数据/场景），作为用例任务项的子列表输出；单项使用无序列表，多项使用从1开始、序号连续的有序列表 |
| 测试步骤 | 对测试动作的简要客观描述，作为用例任务项的子列表输出；单项使用无序列表，多项使用从1开始、序号连续的有序列表 |
| 预期结果 | 针对检查点的预期描述，作为用例任务项的子列表输出；单项使用无序列表，多项使用从1开始、序号连续的有序列表 |

## 测试设计与可执行性

- 文档顶部使用一级标题 `# 测试用例 - {日期} - [{需求名称}]`，并在其后使用引用块声明用例数量 `> 用例数量: 用例 {用例数量} 条`。
- 任务清单树以功能模块/进程/页面作为顶层节点（`- [ ] {功能模块}`），逐级向下嵌套（每级递进缩进 2 个空格）：功能模块（0 空格，`- [ ]`） → 测试类型（2 空格，`- [ ]`） → 可选子功能/规则分组（4 空格，`- [ ]`） → 用例（6 空格，`- [ ] 用例类型-用例标题-用例优先级`；省略分组时用例位于 4 空格）。所有节点（包括用例）默认使用 `- [ ]`；生成测试用例不代表已经执行，不得输出 `- [x]`。分组不是功能点，不计入用例数量。
- 测试类型（功能测试、回归测试、性能测试、安全测试等）为功能模块下的平级一级分组；“回归测试”与“功能测试”平级，“关联回归”等回归场景的分组或用例须放在“回归测试”下，不得嵌套为“功能测试”的子分组或用例。
- 数据库字段等改动按 [测试规则](test-rules.md#功能点拆分与用例组织) 归入使用该对象的业务功能模块；用例标题可包含字段名，但不得出现“××表新增××字段”之类的顶层功能模块节点。
- 判定型逻辑按业务优先级从高到低组织分组和用例（规则见 [测试规则](test-rules.md#功能点拆分与用例组织)）。
- 用例标题在同一文档内唯一；如果同一逻辑按不同数据源、跨月/跨年、入口或枚举拆分为多条用例，用例标题中必须写明区别。
- 需求存疑与待确认清单：若材料存在未定义的异常文案、未量化的超时/SLA、未详述的存量兼容，或与设计材料存在影响预期结果的冲突，在用例树之前输出二级标题“## 需求存疑与待确认清单（可选：仅在材料存在非阻塞性模糊时保留）”及其引用块。每个条目列明：【待确认编号】功能模块/用例标题 - 未明确项；现有材料与冲突点（如适用）；待产品/研发确认的问题。清单不使用 `- [ ]` 任务列表，不影响用例数量统计与校验脚本。对于有依据且可判定的测试假设，在用例标题中标注 `[待确认]` 并注明假设前提；无法确定可判定结果时只记录待确认项。清单确认后的反向优化、删除与重新校验按 SKILL.md 第 6 步执行。

## 校验规则

- 每个用例任务项依次输出 `用例类型-用例标题-用例优先级`，不得包含用例编号，并嵌套输出 `前置条件`、`测试步骤`、`预期结果`；功能模块、测试类型和分组按模板层级组织。
- `需求名称`、`日期`、`功能点` 必须分别使用字段说明指定的来源，不能以文件名、当前日期或其他推断值替代（该项由生成时保证，脚本不校验）。
- 用例标题不得重复；交付摘要与文档头部引用块中的用例数量必须与文档内用例任务项数量一致。根据关键字`预期结果`统计文档用例数量，`预期结果`出现的次数代表文档真实的用例数量。
- 生成产物中的用例任务项必须使用 `- [ ]`，出现 `- [x]` 视为格式不合规。
- 用例任务项的用例类型仅允许 `正向` 或 `反向`，出现 `边界` 等其他值视为格式不合规。
- 必须使用 `> 用例数量: 用例 N 条` 声明用例数量；`description: 用例 N 条` 等历史计数写法不再被接受。
- 校验脚本支持 `--fix`：校验前自动把多项字段列表改写为从 1 开始的有序列表（单项保持无序），改写后仍会重新执行校验。
- 生成后执行 `python "{技能根目录}/scripts/validate_markdown_lists.py" <文件路径>`；技能根目录为 `SKILL.md` 所在目录，不得从当前项目工作目录拼接。脚本报告错误时修正后重新执行，校验通过前不得交付；脚本不存在时停止交付并报告缺失路径。

## 列表渲染示例

字段标题本身固定使用无序列表，字段内容必须缩进两个空格。内容项只计算字段标题下的直接子列表项，不将字段标题计入项数。

单项字段：

```markdown
- 测试步骤
  - 调用创建接口。
```

多项字段：

```markdown
- 预期结果
  1. 接口返回创建成功。
  2. 列表显示新增记录。
```
