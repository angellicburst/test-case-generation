# Markdown 格式测试用例参考

用户指定 Markdown/MD 格式时按本文件输出；用例设计规则见[测试规则](test-rules.md)。

## 文档结构

```markdown
# 测试用例 - {YYYY-MM-DD 或 未指定日期} - [{需求名称}]

> 用例数量: 用例 {N} 条

- [ ] {功能模块}
  - [ ] {一级测试类型}
    - [ ] {可选分组}
      - [ ] {正向|反向}-{用例标题}-{P0..P4}
        > [{TC-ID}] 追溯: {TRACE-ID[, TRACE-ID]}

        - 前置操作
          - {环境与数据状态}
        - 测试数据
          - {入参或脱敏占位符}
        - 测试步骤
          1. {动作一}
          2. {动作二}
        - 预期结果
          - {可判定结果}
        - 后置操作
          - {清理或恢复动作}

## 需求追溯

### 需求追溯表

| 追溯 ID | 来源 | 定位 | 规则 | 关联用例 |
| :--- | :--- | :--- | :--- | :--- |
| TRACE-XXX-001 | 需求文档.md | 2.1 章节 | 适用条件、行为与可观察结果 | TC-XXX-001 |
```

存在 `待确认` 条目时，在文末追加 `### 待确认项` 表格（列为 `追溯 ID`、`来源`、`定位`、`未明确项`、`当前测试假设`、`确认问题`）；没有待确认条目时不得保留空表。

## 字段与渲染

| 字段 | 要求 |
| :--- | :--- |
| 标题 | 必须为 `# 测试用例 - {日期} - [{需求名称}]`；日期为有效 `YYYY-MM-DD` 或 `未指定日期` |
| 用例数量 | 唯一一条 `> 用例数量: 用例 N 条`，N 等于文档内用例任务项数量 |
| 层级 | 功能模块 0 空格、一级测试类型 2、可选分组 4、用例 6（无分组时 4），每级递进 2 空格 |
| 用例任务项 | `- [ ] {正向\|反向}-{标题}-{P0..P4}`，不得写用例 ID；标题不得以 `正向-`/`反向-` 开头或以 `-P0..P4` 结尾 |
| 引用行 | 用例下首个非空行、缩进 +2：`> [TC-ID] 追溯: TRACE-ID[, TRACE-ID]`；引用须为追溯表中 `已覆盖` 条目（`待覆盖` 仅存在于起草期临时 IR，渲染时自动结算并拦截残留），顺序与表格行序一致 |
| 内容字段 | 顺序固定为 前置操作 → 测试数据 → 测试步骤 → 预期结果 → 后置操作；前置操作、测试步骤、预期结果必填，测试数据、后置操作可省略 |
| 列表 | 字段标题固定为 `- 字段名`；单项内容用 `- `，多项用从 1 开始连续编号的 `1. `，缩进 +2；不得用空列表占位 |
| 节点 | 所有节点用 `- [ ]`，不得用 `- [x]`；每个功能模块、测试类型、分组下必须至少有一条用例；不得出现 `####` 或额外的 `#`/`##`/`###` 标题 |
| 追溯表 | `## 需求追溯` 唯一，其下必须有 `### 需求追溯表` 且至少一行数据；`待覆盖` 不得在交付时存在 |
| 禁止项 | `meta`、`traceability`、`cases` 全部字段均不得出现 `[待确认]` 标记；不得使用旧字段 `前置条件`、`备注`、`后置清理`；不得把待确认信息另写成独立清单 |

`- [ ]` 表示未执行；生成用例不代表已执行。渲染器保留节点与字段间的空行，校验不依赖空行。

## 校验规则

- 单独校验命令：

  ```bash
  python "{技能根目录}/scripts/validate_markdown_lists.py" "<文件.md>" [--baseline "<ir.json>"] [--fix]
  ```

- `--baseline` 会额外比对 Markdown 与基线 IR 的字段差异（忽略无法在 Markdown 表达的 `design_method`）。
- `--fix` 只把多项字段的直接子列表改写为从 1 开始的有序列表，不改写单项列表（单项误用 `1. ` 需手工改回 `- `），不触碰追溯表与嵌套说明；写入使用同目录临时文件替换，失败不覆盖原文件。
- 校验通过前不得交付；无法执行命令时按“未校验”生成并标注。

## 人工改稿与维护

- 新增用例可用占位 ID `[TC-NEW]`、`[NEW]` 或省略 ID（写 `> 追溯: ...`），数量声明可暂不改；随后执行 `sync_artifacts.py --assign-ids` 补号并同步数量与 Excel。
- 只要带 `--excel`，任意缺少 `design_method` 的用例（新增用例或首次由 Markdown 生成 Excel）都会被门禁拦截；需追加 `--default-design-method "<设计方法>"`，或先 `case_baseline.py export` 导出 IR 补全后用 `render_cases.py` 渲染。
- 删除用例允许 ID 跳号；仅定稿/提测前可用 `sync_artifacts.py --renumber` 重排，进入执行后禁止。
- 修改追溯引用后，引用行顺序、追溯表 `关联用例` 列与正文须一致；以 `sync_artifacts.py` 或 `render_cases.py` 回写，不手工维护关联列。
