# 需求追溯与待确认规范

追溯条目写入临时 IR 的 `traceability`，再渲染进产物：Markdown 的 `## 需求追溯` / `### 需求追溯表` / 条件 `### 待确认项`，Excel 的 `需求追溯` / 条件 `待确认项` 工作表。**不生成、不交付独立的矩阵 JSON**，交付目录只保留 `.md`/`.xlsx`。

## 条目结构

| 字段 | 要求 |
| :--- | :--- |
| `id` | 文档内唯一，建议 `TRACE-{需求简写}-{流水号}`；禁止含空白、逗号（`,`/`，`）及方括号（`[`/`]`） |
| `source` | 实际材料文件名，单行文本；不得用其它标识替代。用户补充确认口径写 `用户补充确认`（`location` 注当日实际确认日期、对话与原 PRD 文件名/章节；该日期非 `meta.release_date`），严禁写回原 PRD 条目 |
| `location` | 可定位的章节、表格行或流程节点；单行文本 |
| `rule` | 原文或不改变含义的摘要，单行文本；仅 `待覆盖`/`已覆盖` 必填，`待确认` 不填。必须写明适用条件、行为与可观察结果，不能只写功能概述；同一材料的多条规则拆成多个条目；单源 PRD 疑似内部冲突时摘录仍须保留完整条件与行为原文，冲突点另建 `待确认` |
| `status` | `待覆盖`、`已覆盖` 或 `待确认` |
| `case_ids` | 关联用例 ID，按正文顺序；由 `render_cases.py` / `sync_artifacts.py` 从 `traceability_refs` 自动汇总，不手工维护 |
| `issue` / `assumption` / `question` | 未明确项、当前测试假设、待确认问题，均为单行文本；仅 `待确认` 条目必填，非 `待确认` 条目禁止填写 |

## 状态与关联

- 起草时用 `待覆盖`，关联后转 `已覆盖`，无材料支持的确定预期用 `待确认`；交付前不得残留 `待覆盖`。
- `已覆盖` 条目至少关联一条用例；`rule` 必须足以支撑其全部关联用例的确定性预期。
- `待确认` 条目不得被任何用例引用；`待覆盖` 起草时可由用例引用，渲染/同步时自动转为 `已覆盖`。每条用例至少引用一个非待确认条目。
- 用例通过 `traceability_refs` 引用条目。引用顺序须与追溯表行序一致；同一用例可关联多条规则。
- 删除用例后若某 `已覆盖` 条目失去全部关联，`sync_artifacts.py` 会报错阻断，需删除条目或调整用例，防止静默漏测。

## 跨格式一致性

- Markdown 与 Excel `需求追溯` 表源自同一 IR 且行序一致；交付时至少 1 条 `已覆盖` 条目。
- 用例正文的引用、追溯表的 `关联用例` 列、Excel A 列须互相对应。
- 双格式渲染已内置跨格式校验；分步/单格式后按 `SKILL.md` 补跑 `validate_traceability_bundle.py`（`--coverage-only` 须同传双格式，仅核用例与覆盖）。

## 待确认项的记录与收敛

- 待确认条目只记录在产物 `待确认项` 中，汇报时提取展示，不另建清单或独立用例。
- 收敛标准、风险排序与每模块 3~5 项上限见[测试规则](test-rules.md#待确认项收敛与分级)。
- 确认后按 4 种情形处置；确认修改后均须重渲染校验。
  | 情形 | 处置 |
  | :--- | :--- |
  | 1 补充/细化/覆盖原 PRD 模糊口径 | 原 PRD 已覆盖条目 `source`/`location`/`rule`/`status` 严禁改写；新增或转正 `source`=`用户补充确认`、`status`=`已覆盖` 条目，由相关用例双引用（无原条目时单引用）；原 `待确认` 项均须删除。认可既有业务假设且原条目与断言闭环时可不新建条目；补充新细节或覆盖模糊表述时按单规则单条目新增；衍生歧义须追加 `待确认` 或补入断言与追溯条目。 |
  | 2 用户否定/作废某分支且确认无需覆盖 | 删除该分支追溯条目与关联用例（不得留空挂 `已覆盖`/`待覆盖`），并在汇报与 `meta.notes` 记录删减依据（删除用例≠改原 PRD 原文；Markdown 不渲染 `meta.notes` 时以汇报为准）。 |
  | 3 否定取值/删用例但与 PRD 主干冲突或作废未明 | 严禁伪标 `用户补充确认`/清空 `待确认`。原条目有已确认用例则保持 `已覆盖`，冲突点单列 `待确认`；失去全部确定用例则转 `待确认`，须将原 `rule` 摘要完整迁入 `issue`，待裁决后按 1/2 落位。 |
  | 4 仅回复复合问题部分子项 | 已答按情形 1 转 `已覆盖`，未答子项拆分保留 `待确认` 并明示。 |
