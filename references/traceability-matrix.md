# 需求追溯矩阵参考

每个需求在生成用例前创建 `需求追溯矩阵-{上线日期}-{需求名称}.json`，作为生成期唯一的追溯和待确认数据源。

```json
{
  "entries": [
    {
      "id": "TRACE-001",
      "source": "需求文档.md",
      "location": "2.1 高危涉诈",
      "rule": "strategy_code=2204，十分钟线下核验及线下复机",
      "status": "已覆盖",
      "case_ids": ["TC-ONEKF-001"],
      "case_titles": ["高危涉诈按2204策略处理"]
    }
  ]
}
```

每个条目都必须包含：

- `id`：矩阵内唯一的追溯标识。
- `source`、`location`、`rule`：分别对应实际材料文件、可定位章节/表格行/流程节点，以及支撑用例的原文或不改变含义的摘要。
- `status`：`已覆盖` 或 `待确认`。
- `case_ids`、`case_titles`：分别关联 Excel 用例 ID 和 Markdown 用例标题。`已覆盖` 条目至少填写其中一项；本次生成的格式必须填写对应字段。每个用例只能关联一个条目。
- `issue`、`assumption`、`question`：分别为未明确项、当前测试假设和待确认问题，仅 `待确认` 条目必填。

待确认条目不得关联用例，不在 Markdown 或 Excel 中另存清单；汇报时从矩阵提取 `待确认` 条目展示。用户确认后，补充或修改用例并将条目改为 `已覆盖`；确认无需覆盖的条目直接删除。

Excel 输入 JSON 的每条用例填写 `traceability_ref`，其值必须是矩阵中 `已覆盖` 条目的 `id`。生成器从该条目渲染备注首行；不接收用例自身的自由追溯文本。Markdown 用例的标题与引用内容必须同时与矩阵条目匹配。

校验命令必须追加 `--traceability-matrix "<矩阵路径>"`。校验时仍须核对矩阵内容与原始材料是否一致。所有条目确认完成并通过最终校验后，删除矩阵；用例中的追溯信息已自包含，无需保留第二份数据。
